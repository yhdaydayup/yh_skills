# 股票投资分析报告

产出物是**一只股票一个自包含 HTML 文件**（内嵌 Chart.js CDN，可直接分享）。
本 skill 的规则全部来自真实评审反馈，每一条都对应一次被打回。**不要凭手感重新发明做法。**

## 一、开工前必须确认的三件事

1. **一只股票一份报告。** 除用户明确要求对比，不做横向比较、不给「二选一」结论。
2. **定价基准**：写明取价日、收盘价、汇率、总股本。股本有送转的，历史每股指标和股价必须还原到同一口径。
3. **数据源只用一手披露**：港交所披露易年报／中报、SEC EDGAR（8-K／10-K）、巨潮资讯网、公司业绩公告；行业总量用官方统计（国家统计局、USDA、Eurostat、中汽协、乘联分会）。
   卖方研报只能用于「市场预期」这一类事实，**不能用作财务数据来源**。每个数字都要能回溯到某份文件的某一页。

## 二、工作流

```
1. 取数     一手年报 5 个完整财年 + 最近中报，建立指标表（见 references/analysis-method.md）
2. 验算     勾稽：分项相加 = 合计；占比可用表内数字复算；口径变化单独标注
3. 算真实值  真实 PE、真实自由现金流、派息覆盖倍数、SOTP（见 references/analysis-method.md）
4. 查行业   行业现状（赛道） → 行业地位（份额）；份额口径见 references/market-share.md
5. 竞对     至少拉 2–3 家可比公司同期数据，判断问题是公司自身的还是全行业的
6. 写报告   从 assets/report-skeleton.html 起稿（见下），内容规则见 references/report-structure.md
7. 校验     python3 scripts/validate_report.py <报告.html>          必须零 error
8. 终检     node   scripts/render_check.js  <报告.html>             必须零 FAIL
```

**第 6 步必须复制骨架，不要手抄。** 第三份报告（比亚迪）是手工拼的，结果同时漏掉了
目录高亮脚本、全部折叠块、以及派息覆盖倍数——三个缺陷都被上面两个脚本抓到，
但如果当时没有骨架也没有脚本，它们会一路带到用户面前。

## 三、七条硬规则

违反任何一条都要重做，校验器会拦。

1. **五年起步。** 所有趋势至少 5 个完整财年 + 最近中报。两年对比只在有明确转折点时作为补充。
2. **趋势用折线，构成用折线（绝对值＋占比两张并排），份额用扇形小倍数。**
   构成类**不要用饼图**——饼图只给一个静态切面，趋势图能暴露多年演变。
3. **合并趋势图要么全部归一化，要么不要合并。** 禁止双轴：右轴序列的像素位置由右轴决定，读者照左轴读必然误判。
4. **估值必须给真实口径**：扣净现金（或加回净负债）后的 PE，与名义 PE 并列，并说明选哪个。
5. **派息必须给覆盖倍数**，分母是还原租赁本金付款后的真实自由现金流，不是「经营现金流 − 资本开支」。
6. **份额的分子分母口径全部写明**，读者能自行验算。物理量口径与价值口径分表，不混用。
7. **标题只写内容。** 不写「一图看全貌」「钱是谁赚的」这类虚标题，不把口径说明塞进标题。

## 四、措辞

完整黑名单与判断方法见 `references/wording.md`。三条最常犯的：

- **不用比喻代替事实。** 「底下压着两家上市子公司」→「持有的两家上市子公司股权，市值比它自己高 29%」。
- **不写没有信息量的话。** 虚化实词（本质上）、无功能连接词（换句话说）、作者自评（需要公允地补一点）、对读者的承诺（这一屏读完就能决策）全删。
- **不用文字把图上看得见的东西再念一遍。** 图注只写图上看不到的：为什么会这样、意味着什么。

判断标准：**解释某个判断或某个做法的留，只给结论镶边的删。**

## 五、评审反馈的处理方式

- 用户指出一处问题，**要把全文同类问题一起改**，不要只改他圈的那一处。改完列出「同类还改了哪几处」。
- **同一个问题被追问第二次，不要再解释一遍。** 去改图、或把说明挪到读者视线里（标题正下方、画布之前）。
  自检方法：把图单独截出来，如果读者会产生疑问，说明文字就放错了位置。
- 结论被新证据推翻时**直接说推翻了哪一条**，不要悄悄改掉。
- 没有实际验证过的，不要说「已验证」。

## 七、交付

**沙箱会被整体重置，产出物必须落到沙箱外。** 本 skill 自身就丢过一次：
报告和 skill 全部写在沙箱工作区，下一次运行工作区是空的，只能从飞书历史和线上报告反推重建。
所以：报告上传后给链接并说明本地路径；**skill 与脚本这类要长期复用的东西，推到 Git 仓库**。

两个交付期的坑：

- **重新上传会换 URL，而浏览器批注按「域名＋路径」绑定。**
  所以**让用户先导出批注再出新版本**，并在给新链接时提醒旧链接上的批注不会跟过来。
- **回复里不要写完整邮箱地址。** 飞书审核会拦（`code: 230028, contain sensitive data: EMAIL_ADDRESS`），
  消息直接发不出去而任务显示已完成——曾连续三条回复静默丢失。提交作者只写用户名。
