# 报告结构

## 一、七区块骨架（固定，不要自创）

历史上曾把 13 个章节全部拍平成同级 `h2`，结果是「行业现状与行业地位」一章独占 53% 篇幅、结论只占 2%，
读者无从判断轻重。现在固定为七个区块，`id` 固定 `s1`–`s7`，吸顶目录按此生成。

| id | 标题 | 回答的问题 | 必备内容 |
|---|---|---|---|
| `s1` | 一、投资结论 | 买不买、什么价买 | 评级卡（买入／观望／回避）＋ 买入理由分条 ＋ KPI 条 ＋ 核心指标归一化合并趋势图 |
| `s2` | 二、估值 | 值多少钱 | 名义 PE／真实 PE 对照、资产负债表拆解、五年估值区间、五年指标总表、（如有）SOTP 折价 |
| `s3` | 三、生意结构 | 收入和利润分别来自哪里 | 分业务／分地区／分品类趋势（绝对值＋占比各一张）、客群分层、护城河 |
| `s4` | 四、行业现状 | 赛道怎么样 | 行业总量与增速、周期位置、政策、竞对同期表现 |
| `s5` | 五、行业地位 | 它在赛道里什么位置 | 份额（口径全写明，见 market-share.md）、份额五年趋势 |
| `s6` | 六、质量与现金 | 赚得稳不稳 | ROE／ROA 五年、ROE 拆解、真实自由现金流、派息覆盖倍数 |
| `s7` | 七、操作与风险 | 怎么买 | 五年转折点时间轴、买入区间与条件、风险清单、跟踪点 |

两条拆分纪律：

- **「行业」和「公司生意」必须分开。** 外部赛道（s4／s5）和内部业务结构（s3）是两个问题。
- **标题里出现「A 与 B」通常说明该拆没拆。** 原「行业现状与行业地位」就是反面例子，而且顺序还是反的——
  先讲「赛道怎么样」，再讲「我在赛道里什么位置」。

### s3 的拆解维度：披露里有的一律拆

不要只按业务和地区拆就收手。**逐条检查披露里还有哪些维度，有数据就拆，没有就在正文写明「未披露」**，
不要留空白让读者以为漏了。

| 维度 | 适用 | 实例 |
|---|---|---|
| 业务／分部 | 全部 | 万洲：肉制品占 50.6% 收入、82.0% 经营利润 |
| 地区 | 有海外业务 | 万洲中国收入五年 −19.3%、欧洲 +66.9%，静态切面完全看不出 |
| 客群分层 | 消费品、零售、餐饮 | 海底捞人均消费按城市层级拆：一线 105.2→104.2、二线 96.9→96.0、三线及以下 91.6→90.9，**全线下滑**——不拆层只会看到一个总数 97.0 |
| 产品类型／价格带 | 制造、耐用品 | 比亚迪按车型拆，才看出毛利率反转发生在哪一段 |
| 渠道 | 有线上线下之分 | 海底捞外卖占收入从 4.5% 提到 9.2%，主业堂食 −4.0%——不拆渠道会把外卖增量误读成主业复苏 |
| 批发／零售口径 | 有出口 | 比亚迪零售份额退幅是批发的两倍（见 `market-share.md`「批发份额 ≠ 零售份额」） |

判断标准：**这个维度上的分化会不会改变结论。** 会就必须拆。海底捞的城市层级、渠道两个维度
都改变了结论（总收入 +7.9% 的正增长实际是主业萎缩 + 低毛利外卖冲量），不拆就会给出相反判断。

## 二、篇幅配额

| 项 | 要求 |
|---|---|
| 单个区块常态可见字数占比 | ≤ 35%（校验器 error） |
| 结论区块（s1）占比 | ≥ 5%（校验器 error） |
| 全文常态可见字数 | 控制在 12,000–15,000 字；超出先折叠，再考虑删 |

「常态可见」= 不含 `<details>` 内部的字数。

## 三、折叠策略

判断标准只有一条：**这段是用来「自证严谨」，还是用来「支撑决策」？**

折叠（`<details class="fold">`）：口径为什么选物理量、分母取自哪份官方统计、反推方法与误差、
各机构数据为什么互相矛盾、逐年原始数列。这些必须写，删了就无法自证，但常态下不该占版面。

不折叠：结论、估值口径对照、真实 FCF 与派息覆盖、份额结论、风险与跟踪点。

两条实现要求：

1. **折叠块标题写成结论句，不写「详细数据」「更多说明」这类空标签**（校验器会拦）。
   例：`价值口径份额做不了趋势：各机构同年数据相差 36 倍，且定义中途变过`。
2. **折叠块里有图表时，展开必须 `Chart.resize()`**——`details` 关闭时 canvas 尺寸为 0，Chart.js 不会自愈。
   代码见 `charting.md`「折叠块画布」。

图表太多压不下去的章节（例如份额那节天然有 15 张图），在章节开头加**结论先行卡**：
几个关键数字 + 三句话结论，并注明不看细节可以跳过后面的图表。注意这句本身要写成「本节总结」，
不要写成「这一节只有三个结论，不想看细节可以直接跳过后面的图表：」这种铺垫。

## 四、标题层级

四级，字号必须单调递减（校验器检查）：

```
h2        20px   区块（s1–s7），左侧 4px 主色竖线，带 .lead 副标题
h3.sub2   16px   章节（2.1、2.2…），左对齐，左侧 3px 灰线
h3        16px   图表标题，居中，灰色
h4        15px   图表内小节／评级卡标题，主色，左对齐
h5        12.5px 最内层，左对齐
```

不要用 inline style 覆盖字号来硬凑层级——出现这种需求就说明层级拆错了。

两条已被校验器固化的具体教训：

- **左对齐的卡片标题要给类，不要写 inline style。** 万洲与海底捞一共 19 处 `h3` 带着
  `style="text-align:left;font-size:16px"`，其中万洲那 10 处的字号跟 CSS 默认值一模一样，
  纯属冗余。正解是加一个 `h3.lt{text-align:left}`，别去套 `h3.sub2`——那是章节级，
  会多出左侧竖线和更大的外边距，视觉层级就错了。改之前先看清这些标题在 `div.card` 里还是在区块里。
- **章节标题不能用裸 `h3`。** 比亚迪 18 个小节标题全是裸 `h3`（居中灰色），和图表标题完全同级，
  读者分不出哪是章节哪是图注；而它 CSS 里定义好的 `h3.sub2` 一次都没用。
  裸 `h3` 只留给图表标题，章节一律 `h3.sub2` 并补锚点 `sN-M`。

## 五、编号与交叉引用

重排章节时这两件事必定出错，**每次重排后强制复查**：

1. **「见第 N 章」「下表」「上图」会集体失效。** 一次重排曾导致 5 处失效，其中一处「下文第三章」原本就指错了章。
   对策：报告里交叉引用一律写成锚点链接 `<a class="xr" href="#s3">三、生意结构</a>`，不写裸章节号。
   **本 skill 的文档之间同理——引用写小节标题，不写编号**，否则插一节就要改一圈
   （`market-share.md` 插入「查不到现成数字不等于可以留白」那一节时就触发过）。
2. **批量改号必须一次性同时替换。** 顺序执行会让后一条规则改掉前一条刚写好的号
   （曾把 `6.1` 改成 `7.1` 后又被下一条规则再改一次）。
   对策：用一个映射表一次性全量替换，或先替换成占位符再落地。
3. **改号只能改标题，不能全文替换——正文里有同形数字。** 海底捞把小节号 `4.1` 改成「四、」时，
   用的是全文替换，于是正文里三处真数字一起被改掉：两处「4.1 次/天」的翻台率、一处金额，
   都变成了「四、 次/天」「四、 亿」这种读不通的东西，交付时没人发现。
   对策：替换范围限定在标题标签内；改完跑校验器（`check_numeral_corruption` 会拦，
   判据是顿号后面留了空格）。**被污染的数字未必能复原**——那处金额在报告的任何图表、
   表格里都查不到，只能回查原始年报，不能猜。

## 六、单位与表格

- **一份报告一个货币、一个量级。** 万洲统一「亿美元」，海底捞统一「亿元」，比亚迪统一「人民币亿元」。
  混用百万美元和亿美元是历史上改动量最大的一次返工（一次换算了 144 个数字）。
- **股价与每股股息保留交易所报价货币**（H 股 HK$、A 股人民币元），不换算，并在页首声明。
- **单位跟着行标签走，不写在表头。** `指标（百万美元）` 这种表头声称整表同一单位，但表里混着
  股价 HK$、每股收益美分、ROE %、PE 倍。正确做法：`<td>营业收入<span class="uu">亿美元</span></td>`，
  遮住表头每一行也能自己说清是什么单位。
- **同一行的金额和占比必须同期。** 曾把 `FY2025 分部利润` 和 `1H26 利润占比` 放在同一行，
  各自都对，但读者拿两列相除会算出不一样的数，以为表错了。
- 四舍五入导致分项相加与合计差 0.1 时，在页首统一说明，不要逐表加注。
- 宽表用 `.tscroll` 包裹，首列 `sticky`，关键行加 `tr.hl`。

## 七、终检

两个脚本都必须跑，缺一个都漏。

```bash
python3 scripts/validate_report.py <报告.html>   # 内容与规范，零 error
node    scripts/render_check.js  <报告.html>     # 渲染，零 FAIL
```

`render_check.js` 覆盖：

| 项 | 判据 |
|---|---|
| 图表全部实例化 | 有 `Chart` 实例的 canvas 数 = `<canvas>` 数 |
| 无零宽画布 | 每个 canvas 宽度 > 0 |
| 无 JS 报错 | console error 与 pageerror 均为空 |
| 无横向溢出 | `scrollWidth − clientWidth = 0` |
| 无死锚点 | 每个 `href="#x"` 都有对应元素 |
| 目录高亮 | 滚到中段时 `.toc a.on` 恰好 1 项 |
| 折叠块内图表 | 全部展开后宽度 > 0（即 `Chart.resize()` 接对了） |

只能人工看的两项：扇形小倍数不溢出 `.pcell`；锚点跳转不被吸顶目录遮挡（`h2{scroll-margin-top:62px}`）。

### 手抄会漏掉什么

第三份报告（比亚迪）没有从骨架起稿，`render_check.js` 抓到「目录高亮命中 0 项」——
`nav.toc` 的 HTML 在，跟随高亮的脚本整段没写。同一份报告还漏掉了全部折叠块和派息覆盖倍数。
**新报告一律复制 `assets/report-skeleton.html`。**
